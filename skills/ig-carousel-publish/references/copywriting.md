# 2단계 상세 — 카피 작성

목표: 1단계에서 수집한 raw 정보를 슬라이드별로 나눠서, 각 슬라이드가 **한 가지만** 말하게 만든다.
정보를 욱여넣은 슬라이드는 안 읽힌다 — 슬라이드 수를 늘리는 쪽으로 해결한다.

## 장수 결정 로직 (총 3~10장)

1. 정보량을 먼저 보고 본문 장수를 정한다 (표지 1 + 본문 1장 이상 + CTA 1, 총 3~10장).
2. **한 장에 들어갈 내용이 빈약하거나 화면이 비어 보이면, 인접한 2개 주제를 1장으로 합쳐서 꽉 차게
   구성한다.** 예: '조건'과 '신청방법'이 각각 적으면 → 한 장에 표 2개 or 상하 분할로 합침.
3. 반대로 한 장에 정보가 과하면 2장으로 나눈다.
4. 기준: **각 페이지는 박스/표/리스트로 화면이 85% 이상 채워져야 한다.** 빈 다크 배경이 휑하게
   남으면 안 된다 (하단 강조바로도 채울 수 있다). 글씨 크기를 `design.md`의 "글씨 크기 확정값"
   표대로 충분히 크게 쓰면 채움 기준을 맞추기 쉬워진다.

## 슬라이드 구성 템플릿 (기본 골격 — 위 로직에 따라 합치거나 나눈다)

| # | 종류 | 템플릿 파일 | 내용 |
|---|------|------------|------|
| 1 | 표지 | `cover-dark.html` | 후킹 제목 + 부제 |
| 2 | 정보 | `info-card-dark.html` | 이 지원금이 뭔지 (한줄 정의) |
| 3 | 정보 | `info-card-dark.html` | 누가 받을 수 있는지 (대상 — `.checklist`) |
| 4 | 정보 | `info-card-dark.html` | 얼마/뭘 받는지 (금액·혜택 — `.numbered-list`/`.table-card`, 숫자는 `.mono`로) |
| 5 | (정보량 많으면 추가) | `info-card-dark.html` | 손해회피 비교 (`.compare-box` — 기존 vs 변경/인하) |
| 6 | 정보 | `info-card-dark.html` | **구체적 예시 (`.example-box` 단독 슬라이드 — 빠뜨리지 않는다)** |
| 7 | 정보 | `info-card-dark.html` | 언제까지/어떻게 신청하는지 (유의사항이 적으면 같은 장에 합침) |
| N | CTA | `cta-follow.html` (고정) | 아래 "CTA 슬라이드 카피 공식" 참고 — 카피 고정, 세로 중앙정렬 |

정보가 부족하면 정보 슬라이드를 합쳐도 되지만 **예시(`.example-box`) 슬라이드는 항상 최소 1장
넣는다** — 막연한 설명만 있고 구체적인 적용 예시가 없으면 끝까지 안 읽힌다. 핵심은
**한 슬라이드 = 한 메시지, 그리고 85% 이상 채움** 두 규칙을 동시에 지키는 것이다.

모든 정보 슬라이드는 `HEADING`/`BODY_HTML` 외에 **`SUMMARY` 한 줄을 반드시 같이 쓴다** — 이제
`info-card-dark.html`의 `.summary-bar`가 마지막 장이 아니라 **모든 정보 슬라이드 하단에 항상**
들어간다 (레퍼런스 카드뉴스가 매 장마다 한 줄 요약으로 끝나는 것과 동일). `SUMMARY`는 그 슬라이드의
핵심을 한 문장으로 다시 못박는 문구다 (예: "신용점수 889점 이하면 무조건 확인" / "한 줄로 신청 끝").

## 썸네일(표지) 카피 공통 규칙 (★강제★)

> 이 버전의 표지는 **`cover-dark.html` 1종 고정**(카테고리별 색만 변경)이다.
> 아래 규칙은 그 단일 표지에 그대로 적용한다. (과거 A1/A2/C1/C2 여러 표지 시절의
> 카피 규칙을 정리해 옮긴 것이며, `@@` 포인트 컬러 마킹도 다크 표지에서 동일하게 동작한다.)

### 글자 수·줄 수

- **최대 4줄** (`<br>`으로 줄바꿈), **줄당 최대 8글자**
- **6~8글자 줄은 폰트 자동 축소** — 짧은 줄(≤5자)과 시각 크기 차이가 난다. 의도적 리듬감이 아니면 줄당 글자 수를 비슷하게 맞춘다
- 마감 임박형 공식 → `D-N badge + 손실/후회 프레임 타이틀`
  - 예) "신청 안 하면<br>340만원<br>날아간다!"
- 타이틀은 반드시 손실·FOMO·후회 각도로 — 단순 사실형("청년미래적금 안내") 금지

### C1 / C2 포인트 컬러 마킹 (★강제★)

C1·C2는 위치 기반 자동 색 지정이 없다.  
**줄 앞에 `@@`를 붙인 줄만 포인트 컬러 적용, 나머지는 기본 흰색·연회색.**

```
# 지원금명 강조 (C1 금색, C2 파랑)
지금<br>@@청년미래적금<br>신청해야<br>하는 이유

# 숫자+단위 강조 — 숫자만 단독 금지, 단위까지 묶어서
만 19~34세<br>@@36개월 납입<br>이렇게<br>달라진다   ← @@36개월 납입  (O)
만 19~34세<br>@@36<br>개월 납입<br>달라진다        ← @@36 단독  (X)

# 대상 강조
@@만 19~34세<br>청년이라면<br>지금<br>신청하세요
```

**강조 우선순위**: 지원금명 > 대상 > 숫자+단위 — 둘 다 있으면 지원금명에 `@@`  
**C2 마지막 줄(big+bar)**: 항상 흰색 글씨, `@@` 붙여도 색 변경 없음

## 1장: 썸네일(후크) 규칙 (★강제·재발방지★)

목적: 보자마자 손가락을 멈추고 스와이프/저장하게 만든다 (FOMO + 손해회피). 아래 규칙은 과거에
"나랑 이거 같이 볼사람" 같은 밍밍한 즉흥 카피가 반복적으로 나왔던 문제의 재발 방지용이다 —
참여 유도형/공감형처럼 약한 톤은 더 이상 쓰지 않는다.

- ★썸네일 카피는 반드시 아래 5가지 후크 유형 중 1개를 **명시적으로** 골라서 쓴다. 유형에 안 맞는
  즉흥 카피("나랑 이거 같이 볼사람" 같은 밍밍한 문구)는 절대 금지.★ 작업 로그에 **선택한 후크 유형**을
  반드시 적는다.
  1. **타겟호명형**: "OO라면 무조건 받는" / "OO인데 이거 모르면" (대상을 콕 집어 호명)
     예) "신용점수 낮아서 포기했다면"
  2. **손해·FOMO형**: "모르면 나만 손해보는" / "지금 안 보면 놓치는" (손해·박탈감 자극)
     예) "이거 모르면 매달 이자 더 냅니다"
  3. **마감임박형**: "{이번달}에 꼭 신청해야 할" / "오늘부터 시작되는" (시간 압박)
     예) "오늘부터 신청 시작, 선착순 마감 전에"
  4. **숫자정리형**: "OO 지원금 N가지" / "딱 3가지만 알면 되는" (개수로 정리감)
     예) "저신용자 생활자금 딱 3가지 핵심"
  5. **신규강조형**: "2026년 새로 생긴" / "이번에 처음 나온" (신상·희소성)
     예) "2026년 새로 나온 저신용자 대출"

- ★후크는 강하게 쓴다. 아래에 해당하면 약한 카피이므로 금지:★
  - 단순 사실 나열("OO 대출이란?") 금지 — 감정(손해/이득/긴급/희소)을 건드릴 것
  - 모호한 권유("같이 봐요", "알아두자") 금지 — 구체적 이득·손실을 보여줄 것
  - 가능하면 숫자(금액·금리·인원·날짜)를 카피 안에 박아 임팩트를 준다

- ★색 강조 (썸네일 = 가장 강하게):★
  - 제목에서 핵심 키워드(금액·대상·핵심혜택) 1~2개를 카테고리 포인트 컬러로 크고 굵게 강조한다
  - 본문 페이지는 색강조 3~4곳으로 절제하지만, 썸네일은 시선을 끄는 게 최우선이라 핵심 숫자/단어를
    확실히 컬러로 띄운다 (예: "최대 1,000만원"의 "1,000만원"을 파랑+Black)
  - 단, 제목 전체를 칠하지는 않는다 — 강조 1~2곳 + 나머지 흰색 대비로 임팩트를 준다

- 구성: (배지) + (큰 제목 2줄, 핵심 컬러강조) + (부제: 날짜기준/대상/조건) + (하단: 스와이프 유도 +
  키워드 태그)
  - 배지도 후크 유형에 맞는 강한 한마디로 쓴다 (예: "이거 모르면 손해", "오늘 시작!"). 밍밍한 배지는
    금지
  - 제목 타이포는 박스보다 크게, 화면을 시원하게 채운다 (휑한 상단 여백 금지, 콘텐츠는 세로
    중앙정렬)

### 입력에 없는 구체 수치는 만들어내지 않는다

후크 유형·문구를 강하게 쓰는 것과 무관하게, 수치 정직성 규칙은 항상 그대로 적용된다.

- **★(정책 변경) 입력에 없는 구체 점수를 만들어내지 않는다.★** 점수가 원문에 바로 명시돼 있으면
  그 점수를 그대로 쓰고, 원문에 **퍼센타일만 있으면 그 퍼센타일 표현을 그대로 쓴다** — 예:
  원문이 "신용평점 하위 50% 이하"면 TITLE/본문에도 "신용평점 하위 50% 이하"라고 그대로 쓴다.
  "신용점수 889점 이하"처럼 구체적인 점수로 환산해서 쓰지 않는다 — 그 점수가 입력 어디에도 없으면
  "사실"로 단정해서 만들어내는 것이기 때문이다. (참고: `references/credit-score-reference.md`의
  NICE/KCB 변환표는 과거 버전에서 쓰던 자료로, 입력값에 변환된 점수가 이미 명시돼 있는 경우를
  제외하면 기본 흐름에서 더 이상 자동 적용하지 않는다.) 소득 기준도 마찬가지로 원문이 "저소득층"이면
  그대로 쓰고, 원문에 "연소득 0000만원 이하"가 있을 때만 그 숫자를 쓴다.
- **신용·소득 등급처럼 모호한 카테고리 명칭은 쓰지 않는다.** "중신용", "저신용자", "서민" 같은 라벨은
  사람마다 와닿는 기준이 달라서 후킹력이 떨어진다. 가능하면 입력에 있는 가장 구체적인 표현을 쓴다.

### 표지 슬롯 정리

- `BADGE_TEXT`: 위 5유형 중 선택한 후크 유형에 맞는 강한 한 줄 (참여 유도형 밍밍한 문구 금지)
- `TITLE`: 후킹 제목, 2줄까지 (`<br>`으로 줄바꿈 직접 지정). 5유형 중 1개를 명시적으로 적용하고,
  숫자(금액/한도/비율/기간)를 적극 활용한다
- `SUBTITLE`: 핵심 숫자나 마감 임박감을 한 줄로 ("월 최대 20만원, 마감 며칠 안 남았어요")
- `FOOTER_TEXT`: "스와이프해서 확인 →" 고정 문구
- `BG_IMAGE_URL`: **글 주제와 관련된 이미지여야 한다 — 아무 사진이나 쓰면 안 된다.**
  `https://loremflickr.com/1080/1350/{영문 키워드1},{영문 키워드2}` 형식으로, 그 글의 핵심 소재를
  영문 키워드 1~3개로 뽑아 넣는다 (예: 대출/생활자금 글 → `loan,money,bank`, 청년 주거 글 →
  `apartment,key,moving`, 출산 지원금 글 → `baby,family,newborn`). 키워드가 모호하면 더 일반적인
  단어로 좁혀서 실제 사진이 잘 나오는지 확인한다. (이전에 쓰던 `picsum.photos/seed/...`는 완전히
  무작위 사진이라 주제와 안 맞는 경우가 많아 더 이상 쓰지 않는다.)

## 훅 문구(subtitle/hook) 규칙 (★대상 적합성 강제★)

훅 문구는 아래 규칙에 따라 **카테고리·마감 상황에 맞게 직접 고른다.**

- **대상 독자에 맞는 문구만 쓴다**: "청년" 콘텐츠에 "엄마에게 공유하기" 절대 금지 → "청년 친구한테 공유하기"
- **카테고리별 기본 풀**: 청년→청년/학생/또래, 군인→전우/군인 친구, 여성→언니/여성 친구
- **마감 임박 콘텐츠**: `deadline="today"/"tomorrow"/"soon"` 전달해 마감 전용 문구 선택
  - "오늘 마감, 지금 신청하기" / "내일까지만 신청 가능" / "마감 임박 지금 신청하기"
- **대제목(TITLE)과 다른 각도로** 써야 한다 — 대제목이 손실 프레임이면 훅은 공유 유도로
- **마감 임박 콘텐츠는 pipeline을 거치지 않고 build 스크립트에서 직접 subtitle 지정** 가능
  - 예) `content["subtitle"] = ">> 청년미래적금 오늘 신청 마감 <<"`

## 정보 슬라이드 카피 공식

레퍼런스를 보면 정보 슬라이드는 정보를 한 문단으로 풀어쓰지 않고, **섹션 라벨 + 불릿 리스트**로
쪼개서 보여줄 때 훨씬 잘 읽힌다 (예: "지원대상 / 신청기간 / 신청방법"을 각각 볼드 소제목으로 달고
그 옆에 내용을 붙이는 형식). 정보량이 많은 슬라이드는 이 구조를 적극 활용한다.

- `LABEL`: "지원 대상", "지원 금액", "신청 방법" 등 — 이 슬라이드가 다루는 항목 이름 (영문 대문자도 가능)
- `HEADING`: 질문형이나 단언형으로 1~2줄 ("월세 부담, 정부가 줄여드려요")
- `BODY_HTML`: 본문. 두 가지 형식 중 정보량에 맞게 고른다:
  - **단문형**: 한 문단으로 서술, 핵심 구절만 `<mark>핵심구절</mark>`로 강조 (1~2개 제한)
  - **불릿형**: 항목이 여러 개일 때 `<ul><li><strong>신청기한:</strong> 06.08~06.19까지</li>...</ul>`
    형태로 작성 — `info-slide.html`이 `<ul>/<li>/<strong>`을 자동으로 스타일링한다.
    이 안에서도 숫자/기준은 `<mark>`로 한 번 더 강조 가능
- `PAGE_NUM` / `TOTAL_PAGES`: 슬라이드 순번/전체 장수 (자동 계산, 상단에 표시)
- `SUMMARY`: 이 슬라이드 핵심을 한 줄로 못박는 요약 — **모든 정보 슬라이드에 빠짐없이 작성한다**
  (하단 강조바에 들어간다)

### 자격조건처럼 "가능/불가"를 나눠 보여줘야 할 때 — 체크표 형식

자격조건처럼 단순 가능/불가 항목이 여러 개일 땐 **하나의 카드 안에서 항목별로 ✅/❌ 이모지를 붙인
한 줄 체크표**(`.checklist`)로 보여준다. 컬러 블로킹 없이 이모지만으로 가능/불가를 구분하니
다크모드 톤에서도 깔끔하고, 무료버전의 "사진 없이 텍스트+이모지" 원칙과도 맞는다.

형식:
```
✅ 신용평점 하위 50% 이하 (중·저신용자)
✅ 생활자금 목적 (긴급 생계비, 의료비 등)
❌ 주택구입 목적
❌ 신용평점 상위 50% (고신용자)
```
각 줄은 `항목명 + 짧은 설명` 한 줄로 끝내고, 길게 풀어쓰지 않는다. ✅ 항목을 먼저 모아서 보여주고
그 아래 ❌ 항목을 모아서 보여주는 순서(가능 → 불가)가, 불가부터 보여주는 것보다 끝까지 읽히는 비율이
높다 — 가능 조건에 자기를 대입해보다가 자연스럽게 불가 조건까지 읽게 되는 흐름이기 때문이다.

**주의 — 체크표(항목 3~4개)와 예시 박스(`.example-box`)를 같은 슬라이드에 같이 넣지 않는다.**
실측 결과 체크표 4줄 + 예시 박스를 한 슬라이드에 같이 쓰면 슬라이드 높이(1350px)를 넘어가서
아래쪽이 잘려서 캡처된다 (`#slide`가 `overflow:hidden`이라 넘친 부분은 안 보이게 됨). 체크표 단독은
충분히 여유 있게 들어가니, 예시가 꼭 필요하면 "한 슬라이드 = 한 메시지" 원칙대로 예시는 다음 슬라이드로
분리한다.

> 정보카드(`info-card-dark.html`)의 폰트·크기 규칙은 `references/design.md`가 관장한다
> (Pretendard 1종 + 숫자·날짜 모노스페이스, 크기 확정값). 여기서는 카피(문구) 규칙만 다룬다.

### 계산/예시 슬라이드 포맷 (★약속된 형식 — dark-box + light-box★)

수치 계산이나 금액 예시를 보여줄 때는 반드시 `.dark-box` + `.light-box` 형식을 쓴다.
`.example-box`나 `.compare-box`를 계산 슬라이드에 쓰면 안 된다.

```html
<div class="dark-box">
  <div class="box-title">① 항목명 (기준 조건)</div>
  <div class="box-row"><span>항목 설명</span><span>금액</span></div>
  <div class="box-row"><span>항목 설명</span><span>금액</span></div>
  <div class="box-row total"><span>합계</span><span>총 금액</span></div>
</div>
<div class="light-box">
  <div class="sum-line">납입 X → 약 <mark>Y</mark> 수령</div>
  <div class="footnote">&gt;&gt; 가정: 조건들.</div>
</div>
```

- 여러 항목 비교가 필요하면 `.dark-box` 블록을 2개 연속 쓰고 `.light-box` 하나로 합산
- `.footnote`는 24px 소문자 — 중요한 가정 조건을 짧게

### 손해회피를 보여줘야 할 때 — BAD/GOOD 비교박스 (`.compare-box`)

"기존엔 이랬는데 지금은 이렇게 좋아졌다" 같은 전/후 비교나, "이거 안 하면 손해, 이거 하면 이득" 같은
대비를 보여줄 땐 `.compare-box`를 쓴다. 좌측 칸은 빨강 톤(기존/불리), 우측 칸은 초록 톤(신규/유리)
으로 나란히 놓는다 — 예: "기존 최고금리 16.51%" (BAD) vs "인하된 15.27%" (GOOD). 숫자는 `.mono`로
감싸서 데이터 느낌을 살린다. 체크표와 마찬가지로 비교박스 단독으로 한 슬라이드를 채우는 게 기본이고,
정보가 적으면 같은 슬라이드 안에 짧은 `.numbered-list`와 함께 묶어도 된다.

## CTA 슬라이드 카피 공식 (★고정형 — A/B 선택 폐지★)

무료 버전 정책상 마지막 슬라이드는 **`cta-follow.html` 하나로 고정**한다 (댓글 유도형
`cta-comment.html`은 더 이상 기본 흐름에서 쓰지 않는다 — 파일은 레거시로만 남아있다). 카피도
거의 고정이라 2단계에서 새로 짜지 않는다. 디자인 톤은 본문과 동일하게 다크(`#0a0a0a`) + 그날
정한 카테고리 포인트 컬러를 쓴다 (원/버튼 색을 카테고리 색으로 통일해서 본문 슬라이드와 한 세트처럼
보이게 한다). 레이아웃은 다른 정보 슬라이드와 같은 원칙으로 **세로 중앙정렬**한다 — 후크 문구 →
팔로우 카드 → 안내 문구 → 보조 문구 순서로 화면 중앙에 모아 배치하고, 위/아래 여백이 한쪽으로
쏠리지 않게 한다 (`design.md`의 "CTA 슬라이드 — 고정형 단일 디자인" 절 참고).

- `HEADLINE`(상단 후크, 큰 글씨 2줄, 고정): "정책 지원금<br>놓치고 싶지 않다면"
- `AVATAR`: 실제 프로필 사진(`~/Desktop/insta_auto/IMG_5586.jpg`)을 원형으로 마스킹해서 사용한다
  (`design.md`의 "CTA 슬라이드의 프로필 사진" 절 참고). 사진이 없으면 이니셜 1~2글자로 대체.
- `HANDLE`: 실제 인스타그램 계정 핸들 `@maknangeee` (반드시 실제 값으로 채운다)
- `GUIDE_TEXT`(카드 아래, 중간 글씨, 고정): "팔로우하고 프로필 링크를 확인해 보세요"
- `SMALL_TEXT`(가장 아래, 작은 회색, 고정): "매일 놓치기 쉬운 지원금·정책, 가장 먼저 알려드려요"

카피가 완전히 고정이므로, 2단계에서는 카테고리 포인트 컬러와 프로필 사진만 그날 값으로 채우면 된다.

## 캡션(본문 글) 공식 — 스토리텔링형 (★개정★)

이전엔 "후킹 1줄 + ✅ 체크 나열 + 출처 + 해시태그" 형식이었는데, 이렇게 쓰면 카드뉴스 캡션이 슬라이드
내용을 그냥 다시 요약하는 느낌이라 끝까지 안 읽힌다. **개정된 공식은 캡션 자체가 하나의 짧은 이야기여야
한다** — 후크 제목(인용구) → 무슨 일이 있었는지/뭐가 바뀌었는지 풀어주는 설명 → 자격조건을 라벨로
딱 정리 → 주의할 점 → 캐주얼한 해시태그 → 팔로우 유도 한 줄. 아래 예시(청년 취업지원금)를 그대로
구조로 따라간다:

```
"취업 경험 없어도 월 60만 원? 선착순 3만 명까지"

정부가 취업 준비 중인 청년들을 위해 파격적인 지원책을 내놨어요.
한 번도 일해본 적 없는 '생초보' 취준생이라도 월 60만 원씩 6개월, 총 360만 원을 받을 수 있게 된
건데요.
기존에는 최근 2년 내 100일 이상 일한 경험이 있어야 했지만, 이번에 그 문턱을 완전히 없앴습니다.

📍 누가 받을 수 있나요?
나이: 만 15세~34세 (군필자는 최대 37세까지)
소득: 중위소득 120% 이하 (1인 가구 기준 월 약 307만 원 이하)
재산: 5억 원 이하
신청은 이미 4월 27일부터 시작됐고, 고용24 홈페이지나 고용센터를 통해 가능합니다.

주의할 점!
딱 3만 명 선착순이라 예산이 소진되면 바로 마감된대요.

#청년지원금 #지원금 #취준생 #대학생 #꿀팁

* 지원금 꿀팁, 정보를 놓치고 싶지 않다면 팔로우 버튼 꾸욱.
```

구성 요소별 작성 규칙:

- **후크 제목(1행, 큰따옴표로 인용)**: 표지 TITLE을 그대로 복사하지 않고 **다른 각도**에서 다시
  찌른다 — 표지가 대상을 호명했다면 캡션은 숫자나 질문형으로, 표지가 숫자형이었다면 캡션은 대상
  호명형으로 비틀어서 쓴다. 끝에 물음표나 숫자로 끝내면 클릭률이 올라간다 (예: "...선착순 3만
  명까지").
- **스토리 단락(2~3개 문단)**: "정부가/이번에 ~했어요" 식으로 무엇이 바뀌었는지 **이야기하듯** 설명한다.
  반드시 "기존엔 이랬는데, 이번에 이렇게 바뀌었다"는 **전/후 대비**를 한 문장 이상 넣는다 (예: "기존에는
  최근 2년 내 100일 이상 일한 경험이 있어야 했지만, 이번에 그 문턱을 완전히 없앴습니다"). 문장은
  짧게 끊어서 가독성을 살리고, 슬라이드에서 이미 다룬 수치를 다시 가져와도 되지만 **불릿 나열이
  아니라 자연스러운 문장**으로 풀어쓴다.
- **"📍 누가 받을 수 있나요?" 라벨 블록**: 자격조건이 있는 글은 이 라벨을 고정으로 쓰고, 그 아래
  `필드명: 값` 형태(콜론 구분)로 한 줄씩 나열한다 (나이/소득/재산처럼 입력에 있는 조건만, 없는
  조건은 생략). 신청 시작일·신청 경로가 있으면 그 블록 바로 다음 문장으로 붙인다.
- **"주의할 점!" 경고 단락**: 마감(선착순/예산소진)이나 놓치기 쉬운 제약이 있으면 반드시 이 라벨로
  따로 뗀다. 없으면 이 블록은 생략 가능하지만, 마감·선착순 요소가 입력에 있는데 빠뜨리면 안 된다.
- **해시태그(5개, 캐주얼 톤)**: 이전의 격식체 태그(`#정부지원금 #2026지원금 #정책정보`처럼 딱딱한
  조합)보다 **실제 타겟이 쓸 법한 캐주얼한 키워드**를 섞는다 — 지원금 자체 태그 1개 + 타겟 신분 태그
  1~2개(`#취준생 #대학생`처럼) + 분위기 태그(`#꿀팁`처럼) 식으로 5개를 채운다. `#출처` `#정책브리핑`
  같은 사무적인 태그는 넣지 않는다.
- **마지막 줄(팔로우 유도, 고정 패턴)**: 항상 `* (그 글의 토픽) 꿀팁, 정보를 놓치고 싶지 않다면
  팔로우 버튼 꾸욱.` 패턴을 쓴다 — `(토픽)` 자리만 그날 주제에 맞게 바꾼다 (예: "지원금 꿀팁" /
  "대출 꿀팁" / "정책 꿀팁"). 끝에 마침표를 찍는다.
- **출처는 본문에 줄 끄집어 넣지 않는다** — 출처 표기는 이미 슬라이드(`.source-text`)에 있으므로
  캡션에서는 굳이 "출처: ..." 줄을 따로 만들지 않는다(원하면 스토리 문단 안에 자연스럽게 한 번
  언급하는 정도로 충분하다).
- 인스타그램 캡션엔 마크다운 링크(`[텍스트](url)`)가 렌더링되지 않으니, 절대 그 형태로 쓰지 않는다 —
  URL을 꼭 넣어야 하면 그냥 텍스트로 적는다.
